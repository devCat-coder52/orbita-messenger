# Changelog

Все заметные изменения Orbita Messenger.
Формат — по мотивам [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — semver.

## [0.8.9] — 2026-11-04

Первый релиз, который можно показывать тестировщикам: закрыты блокеры регистрации,
потери истории переписки и доступа к чужой переписке.

### Безопасность

- **Секрет JWT** читается из `.env` до инициализации конфига. Раньше подпись шла
  публично известной строкой-заглушкой, то есть любой мог выпустить токен на чужой
  аккаунт. В production сервер не стартует без секрета длиной 32+ символа.
- **Закрыт доступ к чужим сообщениям**: `GET /api/chat/:chatId/messages` и
  `/api/chat/:chatId/info` проверяют членство в чате (было — любой авторизованный
  читал любую переписку по номеру чата).
- **Закрыта утечка через цитаты**: `reply.id` проверяется на существование и
  принадлежность тому же чату, `forward.id` — на существование пользователя.
- **Email** отдаётся только владельцу профиля.
- **Лимиты**: `send-code` — 5 запросов за 15 минут на IP, `verify-code` — 30;
  плюс счётчик неверных попыток на адрес (5), после которого код нужно запрашивать заново.
- **Загрузка файлов**: права на чат проверяются до записи на диск, разрешены только
  изображения JPEG/PNG/WebP/GIF, активный контент (`.html`, `.svg`, `.js`) запрещён,
  аватар фильтруется до сохранения.
- **`/uploads`**: всё, кроме картинок и аудио, отдаётся с `Content-Disposition: attachment`
  и `X-Content-Type-Options: nosniff`.
- **Имена файлов** санитизируются при скачивании (было — запись за пределы папки
  загрузок через `../` в имени от отправителя).
- **401** на защищённых запросах разлогинивает приложение и отправляет на экран входа.
- **FCM-токен** отвязывается от аккаунта при выходе.
- **Сброс пароля по email**: `POST /auth/send-reset-code` и `POST /auth/reset-password`.
  Пароль меняется по коду из письма, а все выданные ранее токены перестают работать —
  версия сессии (`token_version`) увеличивается и сверяется при каждом запросе
  и при подключении сокета.

### Исправленные ошибки

- Регистрация была невозможна: код подтверждения удалялся на шаге `/verify-code`,
  после чего `/register` с тем же кодом всегда отвечал ошибкой.
- Ключи E2E не сохранялись: пара генерировалась заново при каждом запуске, публичный
  ключ перезаписывался, и вся предыдущая переписка становилась нерасшифровываемой.
- Удаление аккаунта падало с 500, если у пользователя оставались сообщения
  (внешние ключи без `ON DELETE SET NULL`).
- Выход из чата удалял сообщения, которые «для себя» скрыл другой участник.
- Главный экран не показывал чаты из кэша до подключения сокета.
- Ответ на сообщение не уходил на сервер: payload собирался после сброса состояния.
- Статусы «в сети / был(а) недавно» в чате не обновлялись (`data[0]` от Map).
- Скачивание вложений не работало: относительный URL передавался в Dio без baseUrl.
- Подписки сокета дублировались после выхода из чата.
- Push уходили даже тому, кто в этот момент читает чат; не было картинки и перехода в чат.
- Редактирование и «удалить для всех» могли отбиваться из-за сравнения id строкой и числом.
- `GET /api/users/abc` падал с 500 из PostgreSQL вместо 400.
- Режим пересылки сбрасывался при открытии целевого чата: фоновая догрузка истории
  затирала подготовленные к отправке копии.

### Сообщения и доставка

- **Персистентная очередь отправки**: недоотправленные сообщения лежат в SQLite,
  переживают перезапуск приложения и досылаются после восстановления соединения.
- Один диспетчер подписок на событие сокета — без дублей и «висящих» обработчиков.
- Повторная отправка дедуплицируется по `time_create` на сервере.
- История и список чатов кэшируются в SQLite: переписка открывается офлайн.
- После восстановления соединения открытый чат догружает сообщения, пришедшие
  пока сокет был недоступен.
- Ссылки, почта и телефоны в сообщениях кликабельны: на Android открываются через
  нативный канал, на десктопе — системной командой, иначе копируются в буфер обмена.

### Сквозное шифрование

- Ключевая пара хранится отдельно для каждого пользователя и переживает перезапуск.
- Публичные ключи собеседников кэшируются на 10 минут.

### Медиа

- Скачивание файлов с абсолютным URL, таймаутом и безопасным именем.
- Проверка размера и типа файла до записи на диск.
- Отправка фото в новый чат больше не падает (чат создаётся заранее).

### Уведомления

- Тап по уведомлению открывает нужный чат, в том числе при холодном старте.
- Группировка по чату: `collapseKey`/`tag` на Android, `thread-id` на iOS.
- Абсолютный URL картинки в push (переменная `PUBLIC_BASE_URL`).
- Отправка push параллельно и после ответа клиенту.
- Если Firebase сообщает, что токен больше не зарегистрирован, он удаляется из БД —
  мёртвые токены не копятся и не спамят ошибками в логах.

### Интерфейс

- `ChatScreen` разбит на контроллер и экран: логика в `ChatController`
  (`ChangeNotifier`, без `BuildContext`), экран — ~490 строк вместо 1347.
- Плашка времени как в Telegram: время и статус в последней строке текста,
  отступ у коротких сообщений, «изм.» вместо «ред.», галочки только у своих,
  единый вид для текста, фото, файлов и голосовых.
- Сплэш: передняя дуга орбиты стала тоньше (34 вместо 44) и с меньшим зазором,
  поэтому не перекрывает контур орбиты.
- Скелетоны заменены индикатором загрузки: спиннер рядом с заголовком «Чаты»
  при обновлении списка и обычный индикатор при первой загрузке.
- Pull-to-refresh дожидается окончания загрузки; закреплённые чаты сортируются
  с сохранением порядка по времени.
- Убран неиспользуемый код: `prepareEditing`, `searchUsers`, мёртвые методы бэкенда,
  неиспользуемая модель `User`.
- Удалён мёртвый `search_messages_screen.dart` (файл был полностью закомментирован).
- Экран «О приложении» из меню профиля: версия, политика конфиденциальности
  и условия использования. Оба документа открываются из приложения и не требуют сети.

### Данные и инфраструктура

- Мигратор без внешних зависимостей (`npm run migrate`), две миграции:
  внешние ключи с `CASCADE`/`SET NULL` и `time_create` в `BIGINT` (epoch-мс).
  Миграции применяются автоматически при старте контейнера.
- `GET /health` с проверкой БД, корректная остановка по SIGINT/SIGTERM,
  обработчики `uncaughtException`/`unhandledRejection`, таймауты пула соединений.
- Логи: 4xx пишутся как `warn` без стека, 5xx — как `error`.
- `Dockerfile`, `.dockerignore` и `docker-compose.yml` (PostgreSQL + Redis + API,
  healthcheck, том для загруженных файлов).
- GitHub Actions: бэкенд (схема, миграции, тесты) и Flutter (`analyze`, `test`).
- Уборка вложений: `npm run cleanup:uploads` удаляет файлы, на которые больше
  не ссылается БД (по умолчанию — сухой прогон, удаление с `--delete`; файлы
  моложе суток не трогаются). Старый аватар удаляется сразу при замене.

### Тесты

- Бэкенд: 27 интеграционных и юнит-тестов на `node:test` против настоящих
  PostgreSQL и Redis (включая сброс пароля и уборку осиротевших файлов).
- Клиент: 36 тестов — кэш и очередь отправки, логика контроллера чата,
  разбор ссылок, вёрстка пузыря сообщения (включая проверки переполнений
  на узком экране).

### Обновление с 0.8.8

- Все выданные ранее токены станут недействительными — потребуется один повторный вход.
- Ключи шифрования, созданные до 0.8.9, не сохранялись, поэтому старые сообщения
  останутся в виде `[Зашифровано]`. Сообщения после обновления читаются нормально.
- Перед запуском примените миграции: `npm run migrate`.

### Известные ограничения

- Приватный ключ E2E хранится в `SharedPreferences`; нужен переход на `flutter_secure_storage`.
- Вложения в `/uploads` доступны по прямой ссылке без авторизации.
- Один инстанс socket.io: нет Redis-адаптера, горизонтальное масштабирование не поддержано.
- Нет краш-репортинга, групповых чатов, звонков и реакций.
